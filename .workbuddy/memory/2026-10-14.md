### 新增两个可复跑脚本（放在 `.workbuddy/analysis/`）
- `contract_check.py` — 前后端接口契约一致性校验（静态）：提取前端 `src/api/**` 的 HTTP 调用 URL+方法，与后端 `/openapi.json` 逐条比对，输出「前端调了后端没有」「后端有前端没用」。
  - 解析坑（已修）：① 泛型含 `;` 或嵌套 `<>` 会让 `<[^>]*>` 正则截断 → 改为只匹配 `service.xxx` 前缀再向后扫描；② 扫描窗口必须截止到下一个调用点，否则会跨调用抓取 URL；③ 需先剥离注释（`//` 与 `/* */` 置为等长空格），否则注释掉的示例代码会被算成真实调用；④ `'/api/user/' + id` 字符串拼接要补 `{param}`。
- `api_smoke.py` — 后端真实 HTTP 集成冒烟测试（默认打 8081，用 `pytest@test.com / test123`），覆盖公开接口、登录/刷新双令牌/401、项目 CRUD、文件与资产总线读写、社区/团队/通知，自带清理。

### 发现并修复的 BUG（重要）
- **资产写入乐观锁从未生效**：`services.py` 中 `file.save(update_fields=['type','content','size','updated_by'])` 漏了 `updated_at`。Django 指定 `update_fields` 时只写列出的字段，`auto_now` 不会自动落库 → `_file_version_token()` 基于 `updated_at` 恒定不变 → 过期令牌写入照样返回 200，并发覆盖静默发生。实测确认令牌写入前后不变。
- **修复**：① `update_fields` 补 `updated_at`（含 `update_project_file` 同模型的另一处）；② 令牌改为 `updated_at + 内容 sha256 前12位`——因 MySQL `project_files.updated_at` 为 `timestamp(0)`（无小数秒），纯时间戳无法区分同秒并发写入。
- 修复后实测：令牌 `17:00:16.b70ba01bc60d` → `17:00:19.e84c12dd5295`；过期令牌 **409 正确拒绝**、最新令牌 200。

### 遗留（未改动，待决策）
- **系统性隐患**：全后端约 20 处 `update_fields` 均未带 `updated_at`（projects / teams / community / accounts / notifications 均有），即所有局部更新都不会刷新「最后修改时间」，UI 上的更新时间失真。13 个模型都有 `updated_at`，可统一改（建议加公共 helper 或在各处补字段），但因涉及面广未擅自 sweep。
- **3 条死代码级的契约断裂**（均有后端无对应路由，实测 404）：`POST /api/admin/init/community-groups`、`PUT /api/community/posts/{id}/likes`、`PUT /api/community/posts/{id}/comments`。三者均无任何 Vue 组件调用（`updatePostLikes/Comments` 仅被自身单测 mock 引用），无用户可见故障，但属隐患。
