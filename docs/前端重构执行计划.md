# IdeaSpark 前端大规模重构执行计划

> 适用范围：**仅前端**（`frontend/`）。后端问题仅作为交叉提示，不在本计划改动范围。
> 编制依据：对 `frontend/src` 全量静态扫描（167 个源文件，Vue 57,038 行 + TS 9,250 行）+ `vite.config.ts` / `App.vue` / `router` / `store` 实测配置。
> 状态：草案。落地前请确认第 8 节假设。

## 0. 现状诊断（实测，非估计）

### 0.1 体量与健康度
- 文件计数：`.vue` 91 / `.ts` 76 / `.scss` 4。
- 目录分布：`views` 64、`components` 27、`api` 35、`composables` 9、`store` 4、`router` 8、`constants` 6、`utils` 4。
- 测试：**仅 7 个测试文件，全部位于 `api/` 下**，`test:run` 63/63 全为 API 单测；**组件 / 视图 / store 零测试，Playwright E2E 未落地**。
- 耦合：前期已将循环依赖从 2 降到 **0**（已修 `api↔router↔view` 链），`api/types.ts`（911 行）为类型枢纽（扇入最高）。

### 0.3 布局层（本次重点）
- `layouts/` **仅有 `AppHeader.vue` 一个组件，没有统一布局骨架**。
- `App.vue` 用硬编码 `hiddenRouteNames`（10 个路由名）+ `hiddenPaths`（4 个路径）判断顶栏显隐，再用 `shouldPadMain` 启发式加 padding。**每新增一个全屏编辑器都要手动维护这个数组**，已出现遗漏（本次 `openFile` 路由 bug 即源于此链路）。
- 无侧边栏 / 页脚 / 响应式抽屉，无基于 `route.meta` 的布局调度。

### 0.4 构建与性能（实测配置）
- ⚠️ `build.minify: false`：为绕开一个 TDZ 报错**关闭了压缩**，生产包体积与运行性能均受损——这是当前最大性能隐患，必须**根因修复**而非长期关闭。
- `additionalData` 把含 `:root` 的 `variables.scss` 注入到**每一个** SCSS 入口 → 设计令牌在每个 chunk 重复打包。
- `manualChunks` 已正确隔离 `naive-ui` / `echarts` / `whiteboard-vendor`(React+Excalidraw) / `store`；但 `echarts`、`gsap` 是否按需懒加载需复核（若被通用组件静态引用会提前加载）。
- 路由已统一动态 `() => import()`（前期工作），首屏分片基础良好；缺 `defineAsyncComponent` 加载态与预取策略。

### 0.5 状态与组合式
- store 仅 3 个业务模块（`user` / `aiWorkshop` / `chat`）支撑 64 个视图，偏薄。
- 4 个 AI composable（`useDocAi` / `useMdAi` / `useSlideAi` / `useExcelAi`）**缺公共基座**，存在大量重复逻辑。

### 0.6 交叉遗留（后端，仅提示，本计划不改）
- 后端约 20 处 `update_fields` 漏 `updated_at`；3 条死代码契约断裂。Phase 0 的 `contract_check.py` / `api_smoke.py` 可作为回归门禁复用。

## 1. 重构目标（可度量）

| 编号 | 目标 | 度量口径 |
|---|---|---|
| G1 | 可维护性 | 单个 `.vue` ≤ 600 行（超标文件拆分）；新增代码**零循环依赖**（CI 强制 `coupling.py`） |
| G2 | 性能 | 恢复生产压缩；首屏关键资源（gzip）设预算上限；LCP < 2.5s；总包体积较现状（未压缩）下降 ≥ 30% |

| G4 | 可测试性 | 组件/视图测试覆盖 ≥ 40%；≥ 1 条 happy-path E2E；CI 门禁（typecheck+lint+test+契约+耦合+包体积预算） |
| G5 | 设计系统 | 设计令牌单一来源，主题 override 与令牌分离；消除 Sass 弃用与 CSS 重复打包 |

## 2. 目标架构与模块边界

### 2.1 分层（稳定度递增，依赖只能向下）
```
app shell (layouts)  ←  views(瘦)  ←  features(业务模块)
        ↑                                  ↑
   shared: components / composables / utils / constants
        ↑
   api(网络)  ←  store(状态)  ←  styles/design-tokens(令牌)
```
- **视图只做编排**（数据取用 + 子组件组合），业务规则下沉到 `composables` / `store`。
- **`api` 层不静态依赖 `router` / `store`**（前期已用 `setRouter` 持有器解决，保持）。
- **类型枢纽 `api/types.ts`** 控制扇入，避免再次膨胀为上帝文件。

### 2.2 布局层重设计（替代硬编码 hide 列表）
新增 `layouts/` 骨架，`App.vue` 退化为薄壳：`<component :is="layoutFor(route.meta.layout)"><router-view/></component>`。
- `DefaultLayout`：顶栏 `AppHeader` + 可选 `Sidebar`（项目/工作台/社区上下文）+ 内容区 + 可选 `Footer`。
- `EditorLayout`：全屏、无全局顶栏（编辑器自带 header，如 `EmbeddedEditor` 已有返回/标题/保存/导出）。
- `AuthLayout`：登录/注册/找回密码的居中卡片。
- `BlankLayout`：裸容器（错误页等）。
- 调度：`route.meta.layout` ∈ `default | editor | auth | blank`，默认值 `default`；删除 `App.vue` 中 `hiddenRouteNames` / `hiddenPaths` / `shouldPadMain` 全部硬编码。
- 响应式与 a11y：移动端侧边栏转抽屉、焦点管理与 `aria-current` 补强。

### 2.3 编辑器适配器契约（已建立，固化为规范）
`EditorAdapterProps{ modelValue, readonly? }` / `EditorAdapterEmits('update:modelValue')` 已落地于 `MindmapEditor` / `FlowEditor` / `WhiteboardEditor`。将其写入 `CONTRIBUTING`/架构文档，新增编辑器只需在 `constants/embeddedEditors.ts` 登记一行 + 实现契约组件。

### 2.4 设计令牌单一来源
- 抽出 `styles/tokens.scss`（color / spacing / radius / typography / shadow / z-index）为唯一来源。
- `App.vue` 中 120 行 `themeOverrides` 迁入 `theme/naiveTheme.ts`（强类型、可复用）。
- `additionalData` 改为只注入 `mixins` + `functions`，`:root` 令牌仅在 `main.ts` 全局引入一次，消除重复打包。

### 2.5 （可选）Feature-based 目录重组
在不动现有 `api`/`store` 的前提下，将 `views/*` 按业务域归并到 `features/{project,community,workbench,editor,account,market}/`，每个 feature 自带 `components/`、`composables/`、`types.ts`。**此项为 P1 可选**，若团队更倾向就地拆分可跳过（见第 8 节）。

## 3. 优先级矩阵

| 优先级 | 主题 | 理由 |
|---|---|---|
| **P0** | 地基：CI 门禁 + 基线度量 + 契约/耦合脚本接入 | 无回归护栏，后续任何重构都高危 |
| **P0** | 布局层重构（meta.layout 调度） | 当前硬编码 hide 列表已致 bug，且阻碍全屏编辑器扩展 |
| **P1** | 性能：根因修复 TDZ 并恢复 `minify`，echarts/gsap 按需懒加载，CSS 去重 | 未压缩 + 重复 CSS 直接拖慢生产 |
| **P1** | 上帝文件拆分（先拆最大 5 个） | 单文件 2700–3383 行，任何改动都高风险 |
| **P2** | store / AI composable 基座重组 | 改善复用，非阻塞 |
| **P2** | 设计系统令牌化 + 主题 override 拆分 | 美观与一致性，可后置 |
| **P2** | 测试补齐（组件 + E2E）+ 覆盖率门禁 | 长期质量，依赖 P0 地基 |

## 4. 分阶段实施步骤

### Phase 0 — 地基与护栏（P0）
- 任务：
  1. 在 CI 串联 `typecheck` + `lint --max-warnings 0` + `test:run` + `contract_check.py` + `api_smoke.py` + `coupling.py`（Windows 下 `@/` 需 `normpath`，脚本已修）。
  2. 接入 `rollup-plugin-visualizer`，记录**当前包体积基线**（首屏 / 各 vendor chunk）。
  3. 设定包体积预算断言（在 `chunkSizeWarningLimit` 基础上加 CI 失败阈值）。
  4. 建立重构分支规范：`refactor/<phase>` 每阶段一 PR，不跨阶段合并。
- 产出：CI 流水线、基线报告、体积预算配置。

### Phase 1 — 布局层重构（P0）
- 任务：
  1. 新增 `layouts/{DefaultLayout,EditorLayout,AuthLayout,BlankLayout}.vue`。
  2. `App.vue` 改为按 `route.meta.layout` 动态壳；删除 `hiddenRouteNames`/`hiddenPaths`/`shouldPadMain`。
  3. 给 8 个路由模块的每条约补 `meta.layout`（编辑器类 → `editor`，登录类 → `auth`，其余 → `default`）。
  4. `DefaultLayout` 内置响应式侧边栏（抽屉）与页脚。
- 产出：统一布局骨架 + 路由 meta 约定。

### Phase 2 — 性能优化（P1）
- 任务：
  1. **根因修复 TDZ**：用 `vue-tsc` + 依赖图定位 TDZ 源头（多为循环 import / `const` 先于初始化使用），消除后恢复 `minify: 'terser'`（保留 `keep_fnames` 仅作兜底，不应长期依赖）。
  2. 复核 `echarts` / `gsap` 引用点，确保仅图表/动画视图静态或动态引用，且这些视图均为懒加载路由；否则改为动态 `import()`。
  3. `additionalData` 移除 `:root` 令牌注入，令牌改 `main.ts` 全局引入一次。
  4. 重视图用 `defineAsyncComponent` 加 loading 态；对高频下一跳路由加 `prefetch`。
  5. 接入图片优化（`vite-imagetools` 已装）并评估 `build.assetsInlineLimit`。
- 产出：压缩恢复、体积下降、CSS 去重。

### Phase 3 — 上帝文件拆分（P1，先拆 Top5）
- 任务（每个文件同一模式：抽**展示型子组件** + **业务 composable** + **局部类型**）：
  1. `SlideEditorView.vue`(3383) → `SlideCanvas` / `SlideThumbPanel` / `SlideToolbar` + `useSlideEditor`。
  2. `ProjectFileEditorView.vue`(2704) → 通用文档宿主 + 插件渲染器（Markdown/Word 等）。
  3. `ProjectWorkspaceView.vue`(2568) → `FilePanel` / `MemberPanel` / `SettingsPanel` / `PluginPanel`（含已修的 `openFile`）。
  4. `CommunityView.vue`(2428) → `FeedList` / `PostCard` / `Composer`。
  5. `MarkdownEditor.vue`(2218) → 工具栏 / 预览 / 编辑区组件。
  - 其余 10 个文件在后续迭代按同法拆分，目标 **≤ 600 行/文件**。
- 产出：拆分后组件 + 共置单测。

### Phase 4 — 状态与组合式重组（P2）
- 任务：
  1. 抽 `useArtifactAi` 公共基座，收敛 `useDocAi`/`useMdAi`/`useSlideAi`/`useExcelAi` 重复逻辑。
  2. store 按 feature 拆（`auth` / `project` / `community` / `aiWorkshop` / `chat` / `ui`），保持零循环。
- 产出：基座 composable + 模块化 store。

### Phase 5 — 设计系统（P2）
- 任务：`styles/tokens.scss` 单一来源；`theme/naiveTheme.ts` 承载 override；清理遗留 `@import`（前期已修 nexus 等，复核全家）；统一间距/圆角/阴影变量。
- 产出：令牌文档 + 主题模块。

### Phase 6 — 测试与收尾（P2）
- 任务：
  1. 用 Vue Test Utils + happy-dom 补组件/视图单测（优先覆盖 Phase 1/3 拆出的组件与 `openFile` 等逻辑）。
  2. 至少 1 条 happy-path E2E（登录 → 进项目 → 新建资产 → 打开编辑器）。
  3. 设覆盖率门禁（≥ 40%）与体积预算失败阈值。
  4. 更新架构文档（`docs/`）与 `CONTRIBUTING` 的编辑器契约/分层约定。
- 产出：测试套件 + 文档 + 门禁。

## 5. 风险与回滚措施

| 阶段 | 主要风险 | 回滚 / 缓解 |
|---|---|---|
| P0 | CI 接入误伤既有绿态 | 门禁先以 **warning** 运行一周再转 **fail**；分支隔离 |
| P1 | 删除 `hiddenRouteNames` 后个别页布局错乱 | `meta.layout` 由路由模块逐条声明并对照清单核对；保留旧 `App.vue` 于 feature flag `LEGACY_LAYOUT`，异常一键切回 |
| P2 | 恢复 `terser` 重现 TDZ | 先在本阶段第 1 步根因修复并加单测复现用例；CI 体积预算防回退；必要时仅对问题 chunk 局部 `keep_fnames` |
| P2 | echarts/gsap 懒加载改坏图表 | 改动后跑 `api_smoke` + 图表视图人工/ E2E 验证；分包体积对比基线 |
| P3 | 拆分引入行为差异 | 每拆一个文件配套共置单测 + 快照；保持 `coupling.py` 零环门禁 |
| P4 | store 重组致状态丢失/刷新异常 | 维持 `pinia-plugin-persistedstate` 配置不变；分模块灰度 |
| 通用 | 重构期与业务需求冲突 | 每阶段独立分支 + PR；保持 `main` 可发布；用契约脚本防前后端漂移 |

## 7. 执行纪律与约束
- 每阶段独立 `refactor/<phase>` 分支 + PR，**不跨阶段合并**到 `main`。
- 复用既有脚本：`coupling.py`、`contract_check.py`、`api_smoke.py`（均在 `.workbuddy/analysis/`）。
- 新增大包体积预算断言，防止性能回退。
- **不改动** `MySQL managed=False`、不动生产库；dev 后端勿暴露公网（既有约定）。
- 不引入未评估的新重型依赖（尤其避免再增 React 生态包）。
