## 三、重要更正：mermaid 并非 markdown 引入 ⚠️

原计划假设"mermaid 被 markdown 链路拖入，需改为 markdown 预览按需懒加载"——**经依赖树核查，该前提不成立**：

- mermaid 11.17.2 由 `@excalidraw/mermaid-to-excalidraw@2.2.2` 依赖，后者是 `@excalidraw/excalidraw`（白板编辑器）的**传递依赖**。
- src 中无任何对 mermaid 的 import；markdown 渲染**不**依赖 mermaid。
- 白板（Excalidraw）经由 `manualChunks` 的 `whiteboard-vendor` 已隔离为**独立懒加载 chunk**，mermaid 又作为 Excalidraw 的动态依赖被进一步拆成独立 chunk。

**结论**：mermaid 已是按需懒加载（仅当用户打开白板并使用"粘贴 mermaid 图"功能时才会下载），首屏零影响。**无需**做任何 markdown 侧改造。原 Phase 2 的"mermaid/katex 改为 markdown 懒加载"子任务取消。

## 四、CSS 令牌去重结果 ✅

- 改动前：`vite.config.ts` 的 `additionalData` 把含 `:root`/`html`/`body`/`::selection` 输出的 `variables.scss` 注入**每一个** SCSS 入口 → 设计令牌在 100+ 组件 chunk 中重复打包。
- 改动后：`additionalData` 仅保留 `mixins.scss`（@mixin/@keyframes 无输出，安全复用）；`variables.scss` 改由 `main.ts` **全局只引一次**。
- 验证：dist 中 `:root` 仅出现在全局文件（`style.css` + `variables.scss`，各加载一次）+ 3 个视图的**独立旧令牌块**（见第五节），不再逐组件重复。

---

## 五、遗留设计债（不在本次范围，建议后续处理）

- `MarketView.vue` / `CreateProjectView.vue` / `ProjectDetailView.vue` 各自在 `<style>` 中定义了**另一套独立旧令牌**（`--color-bg` / `--color-gray-900` 等），与 Nexus `--nexus-*` 并存。它们只在 3 个懒加载 chunk 内、且变量名不同，故不影响首屏，但属于重复设计系统。若要统一设计令牌，需将这 3 个视图的 `var(--color-*)` 迁移到 Nexus 令牌或全局 `--color-*` 单一来源——属视图级样式重构，风险较高，留待 Phase 4/设计系统阶段。

## 六、后续优化方向（Phase 3+ 参考）

1. **naive-ui 1.14 MB 进首屏**：确认 `NaiveUiResolver` 是否真正按需；如仍有整包进入首屏，评估进一步摇树或迁移到按组件引入。
2. **echarts / gsap**：确认是否仅被懒加载视图引用、不进首屏 chunk。
3. **首屏硬指标**：对 gzip 后首屏关键资源设预算，目标 LCP < 2.5s（当前仅测原始体积，未测 gzip/LCP）。
4. **CI 体积门禁（可选）**：解析 build 输出，任一首屏相关 chunk 超阈值即失败——属加固项，未强制实现。
5. **3 个视图旧令牌统一**（见第五节）。
